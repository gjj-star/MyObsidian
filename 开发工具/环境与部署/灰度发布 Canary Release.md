# 灰度发布 Canary Release

**英文**：Canary Release / Gray Release（灰度发布、金丝雀发布）；A/B Testing（A/B 测试）；Blue-Green Deployment（蓝绿部署）；Feature Flag（特性开关）

灰度发布是一种逐步放量的软件发布策略——新版本先推给一小部分用户，观察稳定后再逐步扩大范围，最终全量上线。

**名字由来**：金丝雀（Canary）——矿工会带金丝雀下井，金丝雀对毒气比人敏感，先倒下就是报警。灰度发布同理：用少量真实用户"试毒"，有问题只影响小部分人。

## 四种灰度策略

| 策略 | 做法 | 适用场景 |
|------|------|----------|
| 按流量百分比 | 逐步调高：1% → 5% → 20% → 100% | 通用、无差别发布 |
| 用户白名单 | 指定内测用户/内部员工先体验 | 需要定向反馈的功能 |
| 按地域 | 先推某个城市/机房，再扩区 | 地域敏感型（合规、延迟） |
| 按设备/渠道 | 指定 iOS 先发、特定应用商店先发 | 移动端、渠道包管理 |

## 与 A/B 测试、蓝绿部署的区别

| 概念 | 目的 | 粒度 |
|------|------|------|
| **灰度发布** | 降低发布风险，安全上线 | 逐步放量 |
| **A/B 测试** | 对比哪个版本效果更好 | 同时多版本对比 |
| **蓝绿部署** | 快速切换/回滚整个环境 | 两套完整环境，一键切换 |

灰度关注的是"新版能不能用"，A/B 关注的是"新版好不好用"。实践中两者常结合——灰度阶段就带 A/B 分流。

## 关键基础设施

- **网关/负载均衡器**：按规则把请求路由到新版或旧版
- **Feature Flag（特性开关）**：不用重新部署就能开/关某个功能，实现比流量灰度更细粒度的控制
- **可观测性**：监控、日志、告警——灰度期间必须实时对比新旧版本的错误率、延迟、业务指标
