# LeetCode 836 题解草稿

> 用途：复制到力扣题解编辑器发布。分节标题已用 Markdown 写好，直接整篇贴即可。

## 标题

```
矩形重叠：1KB小脑直接把它降维成一维
```

## 正文

## 思路

**你选用何种方法解题？**

二维降一维（投影 + 区间求交）。

先说这题其实没什么"最优解"可炫耀的——官方给了两种，我写的这种本质就是官方方法二，只是我把中间量起了名字，比官方那串 `min(rec1[2], rec2[2]) > max(rec1[0], rec2[0])` 好读一点。

真正想写这篇是因为**官方方法一（排除四周）我实在记不住**，左、右、上、下四种条件翻来覆去，还得多判一次面积为 0。而"投影求交"这条路是从"交集"这个概念直接推出来的，不用背。

## 解题过程

**第一步：先把矩形压扁成两条线**

题目给的 `rec = [x1, y1, x2, y2]`，是（左下 x，左下 y，右上 x，右上 y）。

我先不管它是个二维图形，直接投影：

- 拍到 x 轴上 → 区间 `(x1, x2)`
- 拍到 y 轴上 → 区间 `(y1, y2)`

于是问题变成：**两个一维区间有没有交集？**

**第二步：区间求交，就一句话**

两个区间 `(x1, x2)` 和 `(a1, a2)`：

- 交集的左边界 = 两个左端点里**更大**的 → `max(x1, a1)`
- 交集的右边界 = 两个右端点里**更小**的 → `min(x2, a2)`
- 左边比右边还小 → 中间真有一段 → 有交集

y 轴照抄一遍就行。

**第三步：这里是 `<` 不是 `<=`**

两个矩形边贴边的时候，`left == right`。碰是碰到了，但重叠面积是 0，题目说不算重叠。所以必须严格小于。

（官方方法一为什么要额外判"面积为 0"？因为它是在排除四周，退化成一个点的矩形不好归类；而投影法天然把它挡掉了——`max` 和 `min` 一算就相等，`<` 直接判否。）

## 复杂度

只算了固定次数的 `max`、`min`、比较，跟输入规模没关系。

- 时间复杂度：O(1)
- 空间复杂度：O(1)
- 代码复杂度：四行，1KB 小脑狂喜

## Code

```python
class Solution:
    def isRectangleOverlap(self, rec1: List[int], rec2: List[int]) -> bool:
        # x 方向交集的左右边界
        left = max(rec1[0], rec2[0])
        right = min(rec1[2], rec2[2])

        # y 方向交集的上下边界
        below = max(rec1[1], rec2[1])
        above = min(rec1[3], rec2[3])

        return left < right and below < above
```

TypeScript 版本（我两个语言都在练）：

```typescript
function isRectangleOverlap(rec1: number[], rec2: number[]): boolean {
    const left = Math.max(rec1[0], rec2[0]);
    const right = Math.min(rec1[2], rec2[2]);
    const below = Math.max(rec1[1], rec2[1]);
    const above = Math.min(rec1[3], rec2[3]);
    return left < right && below < above;
}
```

**一句话总结**：矩形重叠 = 两个方向上的投影都有交集，而区间有交集就是"左端点取大、右端点取小，还剩长度"。

（PS1：我踩的坑——`rec` 的下标顺序我一开始记成了 `[x1, x2, y1, y2]`，其实是 `[x1, y1, x2, y2]`，x 和 y 交替出现。改了半天才发现是自己眼睛的问题。）

（PS2：Python 里两个条件同时成立要用 `and` 不是 `&`。坑不在"该用哪个"，而在优先级——`&` 比比较运算符优先级高，`a < b & c < d` 会被解析成 `a < (b & c) < d`，先算了按位与，而且不报错，静默算错，特别难查。）

（PS3：这题我觉得比背"四周排除法"舒服，因为是从交集直接推出来的。如果你第一直觉也是往投影上想，那我们是同一路人，握手。）
