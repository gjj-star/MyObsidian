# 2472. 不重叠回文子字符串的最大数目笔记

> [!info] 题目原文（LeetCode 2472 不重叠回文子字符串的最大数目）
> 给你一个字符串 `s` 和一个 **正** 整数 `k` 。
>
> 从字符串 `s` 中选出一组满足下述条件且**不重叠**的子字符串：
>
> - 每个子字符串的长度**至少**为 `k` 。
> - 每个子字符串是一个**回文串** 。
>
> 返回最优方案中能选择的子字符串的**最大**数目。
>
> 子字符串是字符串中一个连续的字符序列。
>
> **示例 1：**
>
> - 输入：`s = "abaccdbbd", k = 3`
> - 输出：`2`
> - 解释：可以选择 `s = "abaccdbbd"` 中斜体加粗的子字符串。`"aba"` 和 `"dbbd"` 都是回文，且长度至少为 `k = 3` 。可以证明，无法选出两个以上的有效子字符串。
>
> **示例 2：**
>
> - 输入：`s = "adbcda", k = 2`
> - 输出：`0`
> - 解释：字符串中不存在长度至少为 2 的回文子字符串。
>
> **提示：**
>
> - `1 <= k <= s.length <= 2000`
> - `s` 仅由小写英文字母组成

> [!abstract] 一句话骨架
> 回文只是题目的外壳，「最多个互不重叠区间 + 最早结束贪心」才是骨架。

## 一、我一开始是怎么想的

最开始我先从“**怎么表达回文串**”入手。

长度为 `k` 的字符串 `t`，回文要求左右对称位置相等：

```python
t[i] == t[k - 1 - i]
```

后来发现其实不需要单独考虑奇偶：

* `k` 为偶数：左右成对比较；
* `k` 为奇数：最中间的字符会和自己比较，本身没有影响。

所以统一公式就已经解决了。

继续往下，我最开始想到的是：

> 因为要求子字符串连续，所以可以按序遍历字符串，每次取长度为 `k` 的窗口判断是不是回文。

长度为 `n` 的字符串中，长度为 `k` 的窗口：

```text
起点：
0, 1, 2, ..., n-k

一共：
n-k+1 个
```

# 二、第一个坑：题目不是“长度等于 k”

我最开始只检查：

```python
s[start:start + k]
```

然后在：

```text
s = "abaccdbbd"
k = 3
```

中只能找到：

```text
aba
```

所以输出 `1`。

但是预期答案是 `2`，因为还有：

```text
dbbd
```

长度为 `4`，同样满足：

```text
长度 >= k
```

所以我把代码改成枚举：

```python
k, k+1, k+2, ..., n
```

这时候看似解决了“长度至少为 k”的问题。

# 三、第二个坑：我算成了“所有回文串的数量”

然后遇到：

```text
s = "aaaaaaaaaaa"
k = 3
```

我的程序输出：

```text
45
```

预期：

```text
3
```

原因也非常明显。

因为全部是 `a`：

```text
长度3：9个
长度4：8个
长度5：7个
...
长度11：1个
```

所以：

```text
9+8+7+...+1 = 45
```

我的程序实际上算的是：

> **长度至少为 `k` 的回文子字符串一共有多少个。**

但题目问的是：

> **最多能选择多少个互不重叠的回文子字符串。**

例如：

```text
aaaaaaaaaaa
aaa | aaa | aaa | aa
```

最多只能选：

```text
aaa
aaa
aaa
```

答案为 `3`。

### 这里第一次真正看清题目

这题的核心其实已经不是：

> 找多少回文串。

而是：

> **从很多合法回文区间中，挑出最多个互不重叠的区间。**

# 四、贪心的关键：不是最短，也不是最早开始，而是最早结束

一开始我还误以为：

> 找到一个合法回文以后，是不是应该选最短的？

后来发现这个说法不够准确。

例如：

```text
s = "aabbaaaaa"
k = 4
```

存在：

```text
aabbaa
```

长度 `6`，起点最早。

但是如果选它：

```text
aabbaa | aaa
```

只能得到 `1` 个。

而里面有：

```text
a | abba | aaaa
```

可以选：

```text
abba
aaaa
```

得到 `2` 个。

所以：

```text
❌ 起点最早优先
❌ 最短优先

✅ 结束位置最早优先
```

原因是：

> **当前回文结束得越早，给后面的字符串留下的空间越大。**

更严谨一点：

> 选择一个结束更早的合法回文，不会减少之后可以选择的回文范围，只会给后面留下更大的后缀，因此更有利于得到更多互不重叠的回文。

这就是这题真正的贪心核心。

---

# 五、第一版正确解：暴力找“最早结束”的回文

我给几个变量重新命名后感觉好理解很多：

```text
end
```

表示：

> 前面已经选择的回文结束在哪里，也是当前可用区域的起点。

```text
left
```

表示：

> 当前候选回文的左端点。

```text
right
```

表示：

> 当前候选回文的右端点，Python 切片中取不到。

当前候选：

```python
s[left:right]
```

于是思路变成：

```text
right 从左往右移动

固定 right
    枚举所有合法 left

    如果 s[left:right] 是回文
        立刻选它
        count += 1

        end = right

        下一次从 end 后继续寻找
```

为什么固定 `right`？

因为：

> `right` 从小到大走，第一个能够找到回文的 `right`，就是当前能够找到的最早结束位置。

### 第一版代码

```python
class Solution:
    def maxPalindromes(self, s: str, k: int) -> int:
        n = len(s)
        count = 0
        end = 0
        right = k

        while right <= n:
            for left in range(end, right - k + 1):
                t = s[left:right]

                for i in range(len(t) // 2):
                    if t[i] != t[len(t) - 1 - i]:
                        break
                else:
                    count += 1
                    end = right
                    right = end + k
                    break
            else:
                right += 1

        return count
```

这版虽然暴力，但已经把题目的核心解决了：

```text
最早结束
+
选中以后截断前面的范围
+
后面的回文不能再和前面重叠
```

# 六、不重叠其实就是“截断搜索范围”

例如：

```text
s = "abaccdbbd"
k = 3
```

先找到：

```text
aba
[0:3]
```

于是：

```python
end = 3
```

相当于：

```text
a b a | c c d b b d
------ |
用完了 ↑
      end
```

以后新的候选必须满足：

```python
left >= end
```

否则就会和已经选择的回文重叠。

比如：

```text
旧回文：
[0,3)

新候选：
  [2,6)
```

下标 `2` 被重复使用，所以不合法。

这也是为什么后面优化版本里会有：

```python
if left < end:
    continue
```

# 七、真正漂亮的优化：为什么只检查 `k` 和 `k+1`

这个地方我一开始没理解，后来才发现特别妙。

假设有一个长度大于 `k+1` 的回文：

```text
a b c c b a
```

去掉首尾两个字符：

```text
b c c b
```

仍然一定是回文。

因为原来的回文满足：

```text
首 == 尾
次首 == 次尾
...
```

把最外面一对删掉以后，内部的对称关系完全没有变化。

所以一个很长的回文可以不断：

```text
去头
去尾
```

每次长度减 `2`。

最终一定会缩到：

```text
k
```

或者：

```text
k + 1
```

为什么恰好是这两个？

因为减法一直是：

```text
长度 -= 2
```

所以奇偶性永远不会改变。

例如 `k = 3`：

```text
3 → 3
5 → 3
7 → 5 → 3
9 → 7 → 5 → 3
```

另一种奇偶：

```text
4 → 4
6 → 4
8 → 6 → 4
10 → 8 → 6 → 4
```

所以：

```text
奇数这一类 → 最后缩到 k 或 k+1 中的奇数

偶数这一类 → 最后缩到 k 或 k+1 中的偶数
```

### 我的顿悟

> `k` 和 `k+1` 两个长度刚好覆盖了回文的两种奇偶性。

所以：

> **任何长度 `>= k` 的回文串，内部一定存在一个长度为 `k` 或 `k+1` 的回文子串。**

而且内部这个短回文：

```text
[--------长回文--------]
    [---短回文---]
```

结束得还比原来的长回文更早。

既然我们的贪心目标本来就是：

> **找最早结束的合法回文。**

那么根本没有必要检查那些更长的回文。

# 八、优化后的思路

之前固定一个 `right` 后，要枚举：

```text
长度 k
长度 k+1
长度 k+2
长度 k+3
...
```

也就是：

```python
for left in ...
```

现在只需要检查：

```text
k
k+1
```

所以直接：

```python
for length in (k, k + 1):
```

而 `left` 也不用枚举了，因为：

```text
length = right - left
```

所以：

```python
left = right - length
```

以前：

```text
固定 right
→ 枚举很多 left
```

现在：

```text
固定 right
→ 最多检查两个 length
→ left 直接算出来
```

这就是主要性能优化。

# 九、我的优化版代码

```python
class Solution:
    def maxPalindromes(self, s: str, k: int) -> int:
        n = len(s)
        count = 0
        end = 0
        right = k

        while right <= n:
            for length in (k, k + 1):
                left = right - length

                if left < end:
                    continue

                t = s[left:right]

                for i in range(len(t) // 2):
                    if t[i] != t[len(t) - i - 1]:
                        break
                else:
                    count += 1
                    end = right
                    right = end + k
                    break
            else:
                right += 1

        return count
```

这版我的理解是：

```text
right
↓
寻找当前能够最早结束的位置

length = k / k+1
↓
只检查两种必要长度

left = right - length
↓
直接得到候选区间左端点

left < end
↓
说明伸进了以前已经选择的区域
不能使用

是回文
↓
立即选择
count += 1

end = right
↓
前面的区域全部截断

right = end + k
↓
下一段至少还需要 k 个字符
```

# 十、这题顺便学到的 Python：`for...else`

这题连续用了两层 `for...else`，以前很容易看懵。

### 内层

```python
for i in range(len(t) // 2):
    if t[i] != t[len(t) - i - 1]:
        break
else:
    # 是回文
```

含义：

```text
如果发现不对称
→ break
→ 不执行 else

如果循环正常跑完
→ 一个不对称的位置都没发现
→ 执行 else
→ 是回文
```

所以可以省掉：

```python
is_palindrome = True
```

### 外层

```python
for length in (k, k + 1):
    ...
    if 找到回文:
        break
else:
    right += 1
```

含义：

```text
找到回文
→ break
→ 不执行 else

k、k+1 都检查完还没找到
→ for 正常结束
→ 执行 else
→ right += 1
```

所以也可以省掉：

```python
found = False
```

## 一个我踩过的 `break` / `continue` 坑

这里：

```python
if left < end:
    continue
```

不能随便换成：

```python
break
```

因为 `break` 会导致当前：

```python
for length ...
```

的 `else` 不执行。

那么：

```python
right += 1
```

也可能不执行，`while` 下一轮还是原来的 `right`，甚至可能卡住。

所以在当前代码结构中：

```python
continue
```

更合适。

另外：

```python
if left < end:
    continue
else:
    ...
```

这里的 `else` 没必要。

因为执行到后面的代码已经天然说明：

```python
left >= end
```

直接写：

```python
if left < end:
    continue

# 后续逻辑
```

更清晰。

# 十一、复杂度

### 第一版暴力贪心

大致结构：

```text
right
    left
        回文判断
```

最坏可以到：

```text
O(n³)
```

重点是它**逻辑正确，但回文候选枚举非常暴力**。

### 优化版

每一个 `right` 只检查：

```text
k
k+1
```

两个长度。

每次回文判断最多比较：

```text
O(k)
```

所以时间复杂度：

```text
O(nk)
```

我的代码中：

```python
t = s[left:right]
```

还创建了切片，因此会有最多 `O(k)` 的临时空间。

如果像官方代码一样直接在原字符串上通过左右下标判断，可以做到额外空间：

```text
O(1)
```

# 十二、这道题最值得记住的地方

我现在觉得这题可以分成三个层次。

**第一层：题目本质**

不是：

```text
统计回文串
```

而是：

```text
从合法回文区间中
选择最多个互不重叠区间
```

**第二层：贪心核心**

```text
不是最短
不是起点最早

而是：
结束位置最早
```

找到以后：

```text
截断前面的范围
从它后面继续
```

**第三层：性能优化**

```text
所有长度 >= k 的回文

长度 k 或 k+1 的回文
```

所以只检查：

```text
k
k+1
```

## 我自己的阶段总结

> 解题关键在于“贪心”：找到最早结束的回文串，这样剩下的字符串能保留更大的可用范围，更有利于继续容纳更多合法回文子串，从而得到最大数量。
>
> 题目的前提是子串互不重叠，因此选中一个回文以后，需要直接截断前面的搜索范围，后面的候选左端点不能越过这个断点。
>
> 至于回文串判断到底暴不暴力，是后面的优化方向。即使枚举所有长度，只要仍然按照“最早结束 → 选中 → 截断”的贪心原则，核心逻辑就是正确的。
>
> 真正漂亮的性能优化是：任意长度大于 `k+1` 的回文，都可以不断删掉首尾字符，最后得到一个长度为 `k` 或 `k+1` 的回文。这两个长度刚好覆盖回文的奇偶性，因此不需要再检查其他长度。
>
> **贪心负责“选哪个”，`k / k+1` 负责“怎么更快找到它”。**

这句我觉得特别适合当这道题笔记最后一句：

> **回文只是题目的外壳，“最多个互不重叠区间 + 最早结束贪心”才是骨架。**
