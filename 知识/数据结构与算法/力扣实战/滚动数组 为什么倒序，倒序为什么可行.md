# 滚动数组：为什么要倒序，倒序为什么可行

> [!abstract] 一句话结论
> 倒序的目的是**让「被依赖的旧值」在被覆盖之前先被读取**；倒序可行的原因是**遍历到当前位置时，它依赖的较小下标尚未被本轮更新**，因此仍然保存着上一轮的值。
>
> 注意：并不是所有滚动数组都要倒序——**遍历方向取决于状态依赖关系**。

---

## 一、先看一个更简单的例子：0/1 背包

这是最经典的场景。0/1 背包二维形式：

```text
dp[i][w] = max(dp[i-1][w], dp[i-1][w - weight[i]] + value[i])
```

压成一维：

```python
for w in range(W, weight[i]-1, -1):   # 从大到小
    dp[w] = max(dp[w], dp[w - weight[i]] + value[i])
```

为什么必须倒序？关键在 `dp[w - weight[i]]`。

* 这一项要的是 **上一行** `dp[i-1][w - w_i]`，即「还没放当前物品时的状态」。
* 如果 `w` **从小到大**：`dp[w - w_i]` 会因为 `w_i > 0`，在更早的时候已经被这轮更新成 `dp[i][w - w_i]`（放了当前物品），相当于 **一件物品被放了多次** → 变成完全背包。
* 如果 `w` **从大到小**：走到 `w` 时，`w - w_i` 比 `w` 小，还没被本轮碰过，仍是旧值 ✓。

**核心矛盾**：本轮的更新会覆盖数组，而公式需要旧值，所以要让「旧值先被读、再被写」。

---

## 二、这道题里的倒序

公式：

```python
dp[k] = dp[k] + pre[k-1]      # 需要 pre[k-1] 的旧值（上一行的）
pre[k] = pre[k] + dp[k]       # 更新 pre[k]
```

* `dp[k]` 用到 `pre[k-1]`，下标 **比 k 小**；
* 如果 `k` 从小到大，`pre[k-1]` 会先被这轮更新成新值；
* 从大到小，`pre[k-1]` 还没被碰 → 是旧值 ✓。

注意：

```python
pre[k] = pre[k] + dp[k]
```

里面使用的 `dp[k]` 是**刚刚更新过的本轮新值**。

这是对的，因为这里本来就需要：

$$
pre[n][k]
=
pre[n-1][k]+dp[n][k]
$$

---

所以对于这种：

> **需要读取上一轮旧值**

的滚动数组：

| 需要读取的旧状态       | 为保护旧值应采用的方向 |
| -------------- | ----------- |
| `pre[k-1]`（更小） | **k 递减**    |
| `pre[k+1]`（更大） | **k 递增**    |

如果依赖的是**本轮已经算出的新状态**，判断方式会反过来：必须保证那个新状态先被计算出来，因此不能简单套“更小就倒序”的口诀。

---

## 三、为什么倒序可行（不会漏、不会错）

“可行”包含两层意思。

### ① 不会漏掉任何状态

无论正序倒序，都是把 `k` 从 `1` 到 `K` 全部走一遍：

> 每个位置都会更新一次。

所以倒序没有少算任何状态。

### ② 每个位置在更新时，它需要的旧值都还在

本题：

```text
本轮更新 dp[k]：
需要 dp[k] 旧值 + pre[k-1] 旧值

本轮更新 pre[k]：
需要 pre[k] 旧值 + dp[k] 新值
```

被覆盖顺序就是遍历顺序。

我们需要保证：

> **任何被引用的旧值，在它被覆盖之前，已经被所有需要它的位置读取过。**

`pre[k-1]` 的“读者”是处理 `k` 的那一步。

如果从大到小：

```text
先处理 k
再处理 k-1
```

所以：

```text
k 先读取旧的 pre[k-1]
↓
之后才轮到 k-1，把 pre[k-1] 覆盖
```

安全 ✓

如果从小到大：

```text
先处理 k-1
↓
pre[k-1] 被覆盖
↓
再处理 k
↓
读到新的 pre[k-1]
```

错误 ✗

所以倒序本质上就是：

> **读者先于写者访问这个旧状态。**

---

## 四、一个有用的心智模型：把数组想象成“一张反复擦写的纸”

二维 DP 每个 `n` 都有自己的一行：

```text
第 n-1 行：旧状态
第 n   行：新状态
```

两行互不影响。

滚动数组只剩下一行：

```text
旧状态
↓
原地覆盖
↓
新状态
```

所以必须安排好覆盖顺序。

> 从左往右写，可能会擦掉右边马上还需要读取的“左侧旧值”；
> 从右往左写，则较小下标仍然保持旧值，等需要它的较大下标读完后再覆盖。

这不是特殊数学技巧，而是一个：

> **内存复用时的读写顺序问题。**

---

## 五、判断滚动数组遍历方向

遇到滚动数组，可以先问：

### 1. 当前状态需要的是上一轮旧值，还是本轮新值？

如果需要的是：

```text
上一轮旧值
```

就必须保护它不要提前覆盖。

如果需要的是：

```text
本轮新值
```

则需要保证它已经提前计算完成。

### 2. 如果需要上一轮旧值，它的位置比当前下标大还是小？

需要：

```text
k-1
```

较小下标旧值：

```text
从大到小
```

需要：

```text
k+1
```

较大下标旧值：

```text
从小到大
```

核心始终是：

> **保证读取旧值发生在覆盖旧值之前。**

---

## 六、反例：倒序什么时候反而错

例如：

```text
dp[w] = dp[w] + dp[w + 1]
```

假设这里要求：

```text
dp[w+1]
```

必须是上一轮的旧值。

如果从大到小：

```text
先处理 w+1
↓
dp[w+1] 被覆盖
↓
再处理 w
↓
读到新值
```

错误。

这时应该：

```text
从小到大
```

因为处理 `w` 时，右边的 `w+1` 还没有更新。

所以：

> 倒序不是万能规则，真正的规则是看依赖方向和需要的是新值还是旧值。

---

## 七、我的顿悟：还没降维的时候也完全可以用倒序！

**对，本题二维 DP 的时候完全可以倒序。**

比如：

```python
for n in range(1, N + 1):
    for k in range(K, 0, -1):
        dp[n][k] = dp[n - 1][k] + pre[n - 1][k - 1]
        pre[n][k] = pre[n - 1][k] + dp[n][k]
```

也是正确的。

甚至：

```python
for k in range(1, K + 1):
```

正序也正确。

原因是二维状态中：

```text
上一轮：
dp[n-1][...]
pre[n-1][...]

本轮：
dp[n][...]
pre[n][...]
```

存储在不同位置。

计算：

```text
dp[n][k]
```

不会覆盖：

```text
dp[n-1][k]
pre[n-1][k-1]
```

因此根本没有旧值被提前覆盖的问题。

所以二维时：

> **正序和倒序都可以，只要当前行内部不存在必须遵守的依赖顺序。**

而降维以后：

```text
dp[n-1][k]
和
dp[n][k]
```

都被压到了：

```text
dp[k]
```

同一个位置。

此时才出现：

> “旧值什么时候被覆盖？”

这个问题，所以遍历方向开始变得重要。

### 最终理解

```text
二维 DP：
新旧状态分开放
→ 没有覆盖冲突
→ 本题 k 正序、倒序都行

降成一维：
新旧状态共用一个位置
→ 出现覆盖冲突
→ 必须根据依赖关系安排更新方向
```

所以：

> **倒序不是 DP 本身的要求，而是状态压缩以后，为了安全复用内存产生的顺序约束。**

---

## 八、一句话总结

> 滚动数组用一行空间复用原来多行 DP 的内存。遍历方向的目的，是控制状态被覆盖的先后顺序，让公式需要的旧值在被覆盖之前先被读取。

对于“需要上一轮旧状态”的情况：

```text
依赖更小下标旧值 → 倒序
依赖更大下标旧值 → 正序
```
