# AI 编程安全 Vibe Coding Security

**英文**：Vibe Coding（凭感觉编程，AI 主导写码）；Agentic Mode（智能体自主执行模式）；SAST（Static Application Security Testing，静态应用安全测试）；OWASP Top 10；Supply Chain Attack（供应链攻击）；Slop Squatting（幻觉包抢注）；TrustFall；MCP（Model Context Protocol）

## 范式变化：威胁从"代码层"升级到"执行链"

2026 年 AI 编程从 Copilot 式**自动补全**（AI 写、人采纳）转向 **Agentic 模式**（AI 自主规划、调工具、读写文件、执行）。随之而来两层威胁：

- **旧威胁**：生成的代码有漏洞（等代码运行才被利用）
- **新威胁**：**Agent 执行链本身可被劫持**——攻击者不必等你运行漏洞代码，克隆一个仓库、点一下"信任"，攻击就跑完了（MiraSama 蠕虫即此类，2026-05/06 两次出手污染 PyPI 包与 GitHub 仓库的恶意配置文件）

## 关键数据（2025-2026 研究报告口径）

- Veracode 2025：测 100+ 模型 80+ 任务，**45% 的 AI 代码含 OWASP Top 10 漏洞**；CodeRabbit 对 470 个开源 PR 分析：AI 代码安全缺陷比人工高 **2.74 倍**（人工约 100 行 1 个，AI 约 100 行 3 个）
- **反直觉**：模型越大越"聪明"，语法正确率上涨，但**安全表现持平不改善**——换更强模型解决不了安全问题
- 斯坦福 2026-05：审查 847 个生产环境 AI agent，**91% 存在工具链攻击漏洞**，2347 处，23% 严重级
- 斯坦福 2023 用户研究：用 AI 的开发者**更自信**代码安全 → 审得更松、埋雷更快
- MCP 生态：2026 上半年 4 万个开源 MCP 服务扫出 **106 个 0-day**；Censys 公网扫描 2 万多台 MCP 服务裸露，40% 无认证
- 佐治亚理工：AI 代码直接导致的公开 CVE 2026 年 1 月 6 个 → 2 月 15 → 3 月 35（约 6 倍/季度）；真实数量估计为已确认的 5-10 倍
- Lovable 事件：接口只验登录不验授权，免费账号 5 个请求拖走整个项目（源码/DB 凭证/聊天记录），爆出后 48 天无人修复，2025-11 前创建的项目全灭
- 一句话建站应用（Bolt 类）：超半数把 Stripe 等密钥暴露在前端可访问变量（PolyDefender 扫 58% Bolt 应用暴露 API key）

## AI 漏洞两大类

1. **传统代码漏洞**：SQL 注入/XSS/命令注入/硬编码密钥——人类也犯、AI 放得更多更集中；已有成熟 SAST 能压住。实测 5 个 agent 工具产出的漏洞中**零个可利用 SQLi/XSS**，真正的重灾区是第二类
2. **AI 特有漏洞**（人类基本不犯、传统工具抓不到）：

| 形态 | 机制 | 占 AI 漏洞比 |
| --- | --- | --- |
| 授权缺失 | 登录做对、授权做砸：查了 auth 不查 ownership，任何登录用户可越权读写他人数据 | 约 40%（最大单一类） |
| 密钥硬编码/暴露 | API key 进 git 历史、进前端 bundle（sk_live 密钥编进 React 组件被编译进前端包） | 约 15% |
| 幻觉包（Slop Squatting） | AI 编出"听起来合理但不存在"的依赖名，攻击者抢注塞恶意代码，`npm install` 即中招；约 20% 推荐包不存在，43% 幻觉包名每次重跑稳定出现（可预测可抢注）；真实案例：react-code-shift 被白帽抢先占位防依赖混淆 | 幻觉类 |
| 信任边界失效（TrustFall） | 配置文件（mcp.json、claude settings 等）= 可执行代码：克隆仓库 + 点信任 = 后门触发；2026-05 披露四大主流 agent CLI 全中招，厂商以"用户点了信任"拒绝修复 | 执行链类 |
| MCP/Skill 投毒 | 工具描述藏隐藏指令/隐形字符误导 agent（误导率 72.8%）；3984 个 agent skills 中 13.4% 含严重漏洞，91% = 提示词注入 + 传统恶意软件结合 | 执行链类 |
| 规模化同质化 | 几百万开发者用同一模型 → 同质化错误、可预测攻击面，一出问题就是大面积 | — |

## 为什么 AI 注定写漏洞（根因）

1. **训练数据有毒**：AI 学的是"代码长什么样"而非"安全的代码长什么样"，语料自带漏洞模式并当作有效特征
2. **功能优先、安全靠后**：优化目标=功能完成度，happy path 跑通即交差，边界条件与防御逻辑能省就省
3. **开发者过度自信**：代码能编译能上线 → 放松审查，漏洞拖到生产才暴露
4. **审查速度断层**：AI 写码速度远超人类与安全工具的审查速度，落差被攻击者利用

## 防护

**零成本四习惯（不装工具可规避大半）**：

1. 克隆陌生仓库先查隐藏配置文件（`ls -la` / `dir /a` 找 mcp.json、`.cursor` 等），有可疑命令先弄清执行内容再打开——防 TrustFall 与 MiraSama 类"打开即执行"
2. 每个涉及权限的接口过**授权三问**：登录用户能否读他人数据？能否改他人数据？删除前有没有确认所有权？（加 ownership 检查）
3. AI 推荐的包安装前查 registry（`npm view`）：看下载量、维护者账号、最近更新时间——查不到或新账号低下载量 = 高度可疑幻觉包
4. 密钥只走环境变量：`.env` 进 .gitignore、代码只出现 `process.env`，提交前扫 git 历史查明文密钥

**工具层（编写当下拦截）**：作者自研 WebGuard/DeepSec（原 VibeGuard）三层检测——L1 幻觉+密钥层（实时校验 NPM/pip/Cargo/Go/Maven 五大 registry、11 种 provider 密钥签名 + 香农熵识别 + 31 条可溯源到具体 AI 工具的错误模式）；L2 语法树 + 污点追踪（用户输入 → DB/页面/命令，覆盖 SQLi/XSS/命令注入/路径遍历/SSRF 五种注入）；L3 语义层（检"AI 没写什么"：认证、限流、参数化、错误处理，交给 LLM 语义分析，发送前密钥脱敏 + 防 prompt 注入）。附带 AI 代码归因（只标 AI 引入的问题）、quick fix、与 SonarQube/Semgrep 互操作、SARIF 导出进 CI。

**流程层**：工具只是第一道防线；agent 跑沙箱、最小权限、插件/生态治理等流程手段不可替代。
