# RPA 基础

**英文**：Robotic Process Automation（RPA，机器人流程自动化）

## 定义

RPA 是用软件"机器人"自动执行规则明确、重复性高的业务流程：方式是在现有软件界面上模拟人的操作（点击、录入、复制粘贴、跨系统搬运数据），而非通过系统接口调用。

## 核心特征

- **非侵入式**：不改造、不依赖被操作系统的接口，直接在 UI 层操作，适合无 API 的老旧系统
- **规则驱动**：按 if-then 固定流程执行
- **可持续运行**：可 7x24 小时不间断执行

## 与相近概念的区别

| 对比对象 | 差异 |
|---|---|
| API / 传统集成 | RPA 无需系统开放接口，绕过集成直接模拟 UI，适合封闭/遗留系统；代价是脆弱——UI 一变即易崩 |
| 脚本 / 宏 | RPA 更企业级，带可视化流程编排、集中治理、权限与审计 |
| AI Agent / LLM | 传统 RPA 是"死规则"，处理不了非结构化数据或异常场景；结合 LLM 的 Agentic RPA 能应对更灵活、需要判断的任务，见 [[Agentic RPA 智能体流程自动化]] |

## 典型场景（应用）

财务对账、发票/报销处理、HR 入职离职流程、数据迁移与核对、客服工单流转、报表生成。

## 代表工具

- 海外：UiPath、Automation Anywhere、Blue Prism
- 国内：影刀、来也、弘玑

## 局限

系统 UI/布局变动即失效、维护成本高、只适合稳定且规则清晰的流程、异常需人工兜底。
