# 传统 IT 产品方向简历写法与可直接改写内容

## 1. 求职定位

### 推荐投递岗位名称
- 产品经理实习生
- 产品策划实习生
- 平台产品实习生
- B端产品实习生
- 数据产品实习生
- 互联网产品实习生

### 这份简历里不建议同时出现的定位
- AI产品经理
- 数据分析实习生
- 前端开发实习生
- 游戏策划

原因：传统产品岗最怕候选人“像是临时转过来的”。

你这份简历要让对方觉得：

> 你本来就是在用产品视角看问题，只是恰好还有技术理解力。

---

## 2. 传统产品简历的人设主张

你的最佳产品人设不是“纯文档型 PM”，而是：

**具备用户调研、需求分析、功能设计与跨端落地经验，能够围绕具体业务场景完成问题识别、方案设计与研发协同，并用一定的数据与技术理解提升产品判断质量。**

这个定位非常适合你，因为它刚好承接你的三类资产：
- 调研与需求重构
- Web / 小程序 / 原型落地
- 技术沟通能力

---

## 3. 传统产品简历推荐结构

## 基本信息
- 郭锦佳
- 电话 / 邮箱
- 学校 / 专业 / 年级
- 求职意向：产品经理实习生 / 产品策划实习生 / 数据产品实习生

## 个人简介
建议控制在 3 行左右，重点突出“调研—需求—落地”。

### 可直接使用版本
**具备用户调研、需求分析与功能设计能力，能够围绕业务场景识别痛点、梳理流程并推动 Web / 小程序产品方案落地；同时具备一定前端与数据分析基础，能理解接口、页面交互与数据逻辑，较好地完成与研发的沟通协同。**

---

## 4. 产品技能怎么写

传统产品简历的技能不要写成开发工具清单，而要围绕“产品工作流”来排。

### 建议写法
## 产品与工具能力
- **需求分析**：能够通过访谈、问卷等方式识别用户痛点，完成需求梳理、优先级判断与功能定义。
- **产品表达**：熟悉 Xmind、墨刀、Notion 等工具，可完成信息架构梳理、页面流程设计与基础原型表达。
- **协同落地**：具备一定前端与接口理解能力，熟悉 Apifox、基础 SQL、Web / 小程序开发逻辑，能够与研发高效对齐需求细节。
- **数据辅助判断**：可使用 Excel、Python、Tableau 进行基础数据分析与结果整理，辅助产品决策。

### 可以放，但不宜写太重的内容
- Vue 3
- TypeScript
- WXML/WXSS
- Axios

这些内容只作为“你懂技术”的佐证，不要抢掉产品标签。

## 5. 项目经历怎么排

推荐顺序：
1. 沉香行业数字化综合服务平台
2. Beecarbonize 中文 Wiki 平台
3. AI 应用/文本摘要/其他能体现产品思维的项目

这份简历的项目排序要遵循一个标准：

> 谁最能证明你会做“需求判断、方案设计、功能落地”，谁就排前面。

---

## 6. 项目经历可直接改写版本

## 项目一：沉香行业数字化综合服务平台
**产品策划 / 核心开发｜2025.01 - 2025.03**

### 可直接写进简历的版本
- 参与沉香行业数字化平台规划，围绕农户与行业从业者的实际使用场景开展实地调研与需求梳理。
- 在调研过程中发现目标用户核心痛点并非“种植知识获取”，而是“供需信息不透明、撮合效率低”，据此推动产品方向由知识型平台调整为供求信息服务平台。
- 围绕“发布—查询—筛选—收藏”设计 Web 端与小程序端核心功能闭环，梳理信息展示结构与关键操作流程，提升方案完整性与可落地性。
- 使用原型/前端页面对需求方案进行可视化表达，并协助将业务流程转译为接口与页面逻辑，降低与研发协同过程中的沟通成本与返工风险。

### 这段项目最值钱的地方
不是你“写了页面”，而是你做了产品最核心的动作：
- 发现问题
- 修正方向
- 设计核心闭环
- 推动落地

---

## 项目二：游戏《Beecarbonize》中文 Wiki 百科平台
**项目负责人｜2024.10 - 2024.12**

### 可直接写进简历的版本
- 围绕策略游戏《Beecarbonize》“机制复杂、中文资料缺失”的用户痛点，识别新玩家在查找卡牌信息与理解机制规则过程中的主要阻碍。
- 通过问卷调研收集玩家反馈，验证“卡牌图鉴索引”“机制解析”“分类检索”是优先级最高的核心需求，并据此确定 MVP 功能范围。
- 主导信息架构设计与页面流程规划，将分散的游戏知识整理为可检索、可跳转的结构化内容体系。
- 推动项目从 0 到 1 完成交付，形成具备分类浏览、详情跳转与信息沉淀能力的中文 Wiki 平台，改善新玩家获取资料的效率与体验。

### 这段项目的产品价值
它很好地证明你具备：
- 发现细分需求的能力
- 用调研验证判断的意识
- 信息架构与 MVP 优先级思维
- 从 0 到 1 的执行力

## 项目三：中文文本自动摘要工具 / AI 应用方向
如果你投的是传统 IT 产品，这一段不要强调太多“算法模型”，而要强调：
- 这是为了解决什么场景问题
- 你如何定义输入和输出
- 你如何评估结果好不好

### 可直接写进简历的版本
**中文文本自动摘要工具｜独立开发｜2025.04 - 2025.06**
- 针对长文本阅读成本高、关键信息提取效率低的问题，设计并实现中文文本自动摘要工具，探索信息压缩场景下的产品可行性。
- 梳理“原文输入—文本处理—摘要输出—结果评估”的基础流程，明确功能边界与核心输出形式。
- 引入 ROUGE 指标对摘要效果进行量化验证，为后续功能优化与效果评估提供依据。
- 通过该项目积累 AI 应用场景定义、结果评估与产品化表达经验。

## 9. 传统产品简历最容易踩的坑

### 坑一：把项目写成开发流水账
错误示范：
- 使用 Vue3 + TypeScript + Element Plus 完成页面开发

这种写法对于产品岗价值很低。

更好的写法是：
- 围绕供求信息服务场景设计发布、查询、筛选、收藏等核心功能流程，并推动 Web / 小程序方案落地

### 坑二：没有体现“为什么这么设计”
产品岗很看重判断。

你一定要写出：
- 为什么改方向
- 为什么先做这些功能
- 为什么这个项目能成立

### 坑三：只写执行，不写协同
招聘方会担心你是不是只是“会点原型的人”。

你要特别强调：
- 能理解接口与数据逻辑
- 能把业务需求翻译成研发语言
- 能降低沟通损耗

这会很加分。

## 10. 一页版内容优先级建议

如果只能保留一页，优先级如下：
1. 个人简介
2. 产品与工具能力
3. 沉香平台项目
4. Beecarbonize Wiki 项目
5. 文本摘要/AI 应用项目
6. 教育经历
7. 奖项

不要为了显得“丰富”而塞很多不关键的技术细节。

---

## 11. 传统产品简历的最终目标

这份简历最终要让招聘方看到的是：

> 你不是一个误入产品岗的技术学生，而是一个已经开始用产品方法做事的人。

你会调研、会判断、会梳理流程、会定义功能，而且因为你懂一点技术，所以比纯产品新人更容易跟研发配合。

这个人设一旦站稳，你投传统产品岗的通过率会明显比现在高。
